# Local AI ในแอปด้วย llama.cpp (ดาวน์โหลด จัดการ และรันเองในโปรแกรม)

เอกสารนี้อธิบายแท็บ **Local AI (llama.cpp)** ซึ่งทำให้คุณไม่ต้องติดตั้ง Ollama หรือเครื่องมืออื่นด้วยมือ:
แอปดาวน์โหลดไฟล์ `llama-server` และโมเดล `.gguf` ให้เอง แล้วรันเป็นเซิร์ฟเวอร์ OpenAI-compatible
**บน 127.0.0.1 เท่านั้น** จากนั้นกดใช้เป็น AI ของแอปได้ทันที

> สถานะความจริง: ฟีเจอร์นี้ implement และมีเทสต์ครบ (31 เทสต์ใน `tests/test_llama.py` + เทสต์ UI)
> แต่ **ยังไม่ได้ทดสอบดาวน์โหลดจริงหลาย GB หรือรันโมเดลจริงบน Windows ในรีโปนี้** — เทสต์ใช้
> `httpx.MockTransport` และ process ปลอม ข้อจำกัดทั้งหมดอยู่ใน §7 และ §8

## 1. ภาพรวม 3 ขั้น

| ขั้น | ทำอะไร | ต้องต่อเน็ตไหม | ขอยินยอมก่อนไหม |
|---|---|---|---|
| 1. ไฟล์ llama-server | ดึงรายชื่อรุ่นล่าสุดจาก GitHub releases ของ `ggml-org/llama.cpp` แล้วดาวน์โหลด zip ที่ตรงกับระบบ → แตกไฟล์อย่างปลอดภัย | ใช่ (api.github.com, github.com, objects.githubusercontent.com) | ใช่ — **สองครั้ง** (ครั้งแรก: ดูรายชื่อรุ่น, ครั้งที่สอง: ดาวน์โหลดไฟล์) |
| 2. โมเดล GGUF | เลือกจากแคตตาล็อกหรือพิมพ์ repo เอง → อ่านรายชื่อไฟล์จาก Hugging Face → เลือกไฟล์ + quant → ดาวน์โหลด (ต่อจากไฟล์เดิมได้) | ใช่ (huggingface.co, cdn-lfs*.huggingface.co, hf.co) | ใช่ — ครั้งแรก: ดูรายชื่อไฟล์, ครั้งที่สอง: ก่อนดาวน์โหลดแต่ละชุด |
| 3. รันและใช้งาน | รัน `llama-server` บน `127.0.0.1` + poll `/health` + แสดง log → กด **ตั้งเป็น AI ของแอป** | ไม่ (อยู่ในเครื่องล้วน) | ไม่ต้อง — ไม่มีข้อมูลออกนอกเครื่อง |

ขั้นที่ 1 และ 2 **ไม่ดาวน์โหลดอะไรเลยถ้าคุณไม่กดยินยอม** และขั้นที่ 3 ไม่มีการส่งข้อมูลออกนอกเครื่อง

## 2. ขั้นที่ 1 — ไฟล์ `llama-server`

1. เปิดแท็บ **Local AI (llama.cpp)** → ช่อง "ไฟล์ llama-server" เลือกได้ 3 ทาง
   - **ดาวน์โหลดจาก GitHub** (แนะนำ): ยืนยันการเชื่อมต่อ → เลือกรุ่นจากรายการที่ตรงกับระบบปฏิบัติการของคุณ (Windows x64 จะเห็นไฟล์ `llama-*-bin-win-*`)
   - **เลือกไฟล์เอง**: ถ้าคุณมี `llama-server.exe` อยู่แล้ว (จากการ build เองหรือชุดที่โหลดมา)
   - **ติดตั้งจาก zip**: หลังดาวน์โหลด zip แอปจะแตกไฟล์ให้เอง
2. การแตก zip ทำแบบเข้มงวด: ปฏิเสธ path สัมบูรณ์และ `..` ทุกแบบ, เก็บเฉพาะ `llama-server*` และไฟล์ประกอบที่จำเป็นในโฟลเดอร์เดียวกัน แล้ว **ลบ zip ทิ้ง** หลังแตกสำเร็จ
3. ไฟล์ที่แตกแล้วอยู่ใน `<โฟลเดอร์ข้อมูลผู้ใช้>/llama/bin`

ขนาดไฟล์ zip อยู่ที่หลักสิบ–ร้อย MB ขึ้นกับรุ่นและแบ็กเอนด์ (CPU/CUDA/Vulkan) — ตรวจพื้นที่ว่างและแพ็กเกจอินเทอร์เน็ตก่อน

## 3. ขั้นที่ 2 — โมเดล GGUF

- **แคตตาล็อกในตัว** (ค่าเริ่มต้น) มีทั้งโมเดลข้อความและโมเดลที่ดูภาพได้ (ต้องมีไฟล์ `mmproj`):

| ใช้ทำอะไร | ตัวอย่างในแคตตาล็อก | ขนาดโดยประมาณ |
|---|---|---|
| ข้อความ + ดูภาพหน้าจอ (vision) | Qwen2.5-VL 7B, Gemma 3 4B | หลาย GB + mmproj |
| ข้อความล้วน (เบา/เร็ว) | Qwen2.5 7B, Qwen2.5 3B | ~2–5 GB |

- **พิมพ์ repo เองได้**: ใส่ `owner/repo` ของ GGUF บน Hugging Face (แอปตรวจรูปแบบชื่อให้ ป้องกัน path traversal)
- **เลือก quant**: Q4_K_M (สมดุล), Q5_K_M, Q6_K, Q8_0 ฯลฯ — ตารางจะแสดงทุกไฟล์ `.gguf`, ขนาด, และคอลัมน์สถานะ (`มีแล้ว` / `เสร็จแล้ว` / `กำลังโหลด 42%`)
- **ไฟล์ `mmproj`** (projector ของโมเดลที่ดูภาพได้) ถูกทำเครื่องหมายไว้ และแอปจะเลือกคู่ที่แนะนำให้อัตโนมัติ
- **กด "ดาวน์โหลดคู่ที่แนะนำ"** = ไฟล์โมเดล + mmproj ที่เข้าคู่กันในคลิกเดียว
- **ต่อจากที่ค้างได้**: ไฟล์ที่โหลดไม่จบถูกเก็บเป็น `.part` และครั้งถัดไปจะส่ง `Range: bytes=<ขนาดเดิม>-` เพื่อโหลดต่อ ถ้าเซิร์ฟเวอร์ไม่รองรับ จะเริ่มใหม่ทั้งไฟล์ (ไม่ต่อแบบผิด ๆ) และถ้าขนาดที่ได้ไม่ตรงกับ `Content-Length` แอปจะ **ไม่** เปลี่ยนชื่อเป็นไฟล์จริง
- **ยกเลิกได้ตลอด**: กดยกเลิกแล้วไฟล์ `.part` ยังอยู่ให้โหลดต่อภายหลัง
- **ตรวจ SHA-256** เมื่อผู้ให้บริการแจ้งค่าไว้ (ในตารางจะแสดงปุ่มตรวจ) และลบไฟล์ทิ้งถ้าไม่ตรง
- มีเพดานกันพลาด: ไฟล์เดียวไม่เกิน 60 GB และต้องมีพื้นที่ว่างเหลือ ≥ 2 GB ก่อนเริ่ม

ไฟล์โมเดลอยู่ที่ `<โฟลเดอร์ข้อมูลผู้ใช้>/llama/models` และไฟล์ชั่วคราวอยู่ที่ `.../llama/downloads`

## 4. ขั้นที่ 3 — รันและตั้งเป็น AI ของแอป

1. เลือกโมเดลที่ติดตั้งแล้วในดรอปดาวน์
2. ตั้งค่า: **พอร์ต** (ค่าเริ่มต้น 8081), **context** (2048–131072), **n-gpu-layers** (0 = CPU ล้วน, 999 = สูงสุด), **threads** (0 = ให้ llama.cpp เลือกเอง), และช่อง **อาร์กิวเมนต์เพิ่มเติม** (สูงสุด 20 รายการ เช่น `--flash-attn`, `--no-mmap`)
3. กด **เริ่ม llama-server** → สถานะจะไล่ `กำลังโหลด…` → `ทำงานอยู่` โดยเช็ก `/health` ทุกครึ่งวินาที (สูงสุด ~2 นาที) และมี log ของเซิร์ฟเวอร์ให้ดูในหน้าจอ
4. กด **ตั้งเป็น AI ของแอป** → แอปจะสลับผู้ให้บริการเป็น `API · OpenAI-compatible`, ตั้ง Base URL เป็น `http://127.0.0.1:<พอร์ต>/v1` และดึงชื่อโมเดลจากเซิร์ฟเวอร์มาใส่ให้ (โหมดนี้อยู่ในเครื่อง จึงไม่ต้องมีกล่องยินยอมส่งข้อมูลออกนอกเครื่อง)
5. กด **หยุด** เพื่อปิดเซิร์ฟเวอร์ — และเมื่อปิดหน้าต่างแอป แอปจะสั่งหยุดเซิร์ฟเวอร์ให้เสมอ (ไม่ทิ้งโปรเซสค้าง)

อาร์กิวเมนต์ที่แอปสร้างให้: `--model <ไฟล์> --host 127.0.0.1 --port <p> --ctx-size <n> --n-gpu-layers <n> --no-webui [--threads N] [--mmproj <ไฟล์>] [อาร์กิวเมนต์เพิ่มเติม ≤20]`
— ค่า `-h`/`--help` ในอาร์กิวเมนต์เพิ่มเติมจะถูกตัดออกเพื่อไม่ให้แย่งคำสั่งหลัก และ **ที่อยู่ผูกกับ 127.0.0.1 เท่านั้น**

## 5. ตั้งค่าที่บันทึกไว้ (แท็บตั้งค่า / settings.json)

| คีย์ | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `llama_binary` | ว่าง | พาธ `llama-server(.exe)` (จำกัด 400 ตัวอักษร) |
| `llama_model` | ว่าง | ไฟล์ `.gguf` ล่าสุดที่ใช้ |
| `llama_mmproj` | ว่าง | ไฟล์ projector ของโมเดลที่ดูภาพได้ |
| `llama_port` | 8081 | พอร์ต (1024–65535) |
| `llama_ctx` | 8192 | context size (2048–131072) |
| `llama_gpu_layers` | 0 | 0 = CPU ล้วน |
| `llama_threads` | 0 | 0 = อัตโนมัติ (0–64) |
| `llama_auto_start` | true | เริ่มเซิร์ฟเวอร์ให้เองเมื่อกดเริ่มแปล **ถ้าปลายทางที่ตั้งไว้เป็น 127.0.0.1/localhost อยู่แล้วเท่านั้น** |
| `llama_extra_args` | ว่าง | อาร์กิวเมนต์เพิ่มเติม (≤200 ตัวอักษร) |

`llama_auto_start` **ไม่** ดาวน์โหลดอะไร ไม่เปิดพอร์ตออกนอกเครื่อง และไม่เริ่มเซิร์ฟเวอร์ถ้าคุณยังตั้งปลายทางเป็นบริการภายนอก

## 6. ความเป็นส่วนตัว การยินยอม และลิขสิทธิ์

- อนุญาตเฉพาะโฮสต์ที่ระบุไว้ (huggingface.co, cdn-lfs*.huggingface.co, hf.co, github.com, objects.githubusercontent.com, release-assets.githubusercontent.com) และ **HTTPS เท่านั้น** — URL ที่มี userinfo (`https://huggingface.co@evil.com`), query/fragment, หรือโฮสต์อื่นถูกปฏิเสธก่อนจะเปิดการเชื่อมต่อ
- ทุกครั้งที่มีการเชื่อมต่อออกอินเทอร์เน็ต (ดูรายชื่อรุ่น, ดูรายชื่อไฟล์, ดาวน์โหลด) จะมีกล่องยินยอมบอก **ปลายทาง ขนาดรวม และโฟลเดอร์ปลายทาง**; กด Cancel แล้วไม่เกิดคำขอใด ๆ
- ไม่มี telemetry, ไม่มีการส่งภาพหน้าจอ/ข้อความ OCR/โปรไฟล์เกมในทุกขั้นตอนของฟีเจอร์นี้
- ความเป็นส่วนตัวของคำแปล: เซิร์ฟเวอร์ในเครื่องผูกกับ `127.0.0.1` และเปิด `--no-webui` — เครื่องอื่นใน LAN เข้าถึงไม่ได้
- **ลิขสิทธิ์**: ตัว llama.cpp เป็น MIT แต่ **น้ำหนักโมเดล GGUF มีใบอนุญาตต่างกัน** (เช่น Qwen, Gemma) — แอปเป็นเพียงตัวดาวน์โหลด คุณต้องตรวจใบอนุญาตของ repo ที่เลือกเองก่อนใช้ในงานจริง แอปไม่รับรองสิทธิ์การใช้งานแทนคุณ

## 7. แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุ/วิธีแก้ |
|---|---|
| "พอร์ต 8081 ถูกใช้อยู่" | เปลี่ยนพอร์ตในขั้นที่ 3 (หรือปิดโปรแกรมอื่นที่ถือพอร์ตนั้น) — แอปเช็กพอร์ตก่อนสตาร์ตเสมอ |
| สถานะค้างที่ "กำลังโหลด…" แล้วขึ้น "มีปัญหา" | ดู log ท้ายหน้าจอ: มักเป็นแรมไม่พอหรือไฟล์ `.gguf` เสีย — ลอง quant เล็กลงหรือ context น้อยลง |
| `llama-server` ไม่ถูกเรียกใช้ | ตรวจว่าพาธในช่องแรกถูกต้อง (หรือกด "ติดตั้งจาก zip" ใหม่) และโมเดลอยู่ในโฟลเดอร์ `llama/models` |
| ดาวน์โหลดค้าง/ช้า | กดยกเลิกได้ตลอด ไฟล์ `.part` จะอยู่ให้โหลดต่อ; ครั้งถัดไปแอปจะต่อจากเดิมถ้าเซิร์ฟเวอร์รองรับ Range |
| ได้ไฟล์แต่ใช้ไม่ได้ | กดปุ่มตรวจ SHA-256 ในตาราง (ถ้าผู้ให้บริการแจ้งค่าไว้) — ถ้าไม่ตรง แอปจะลบไฟล์ให้ ต้องโหลดใหม่ |
| อยากได้ความเร็ว GPU | ตั้ง `n-gpu-layers` สูงขึ้น (เช่น 32) — ต้องเป็นรุ่นที่รองรับ GPU ของคุณ; ค่าเริ่มต้น 0 คือ CPU ล้วน |
| อยากใช้ vision | ต้องมีทั้งโมเดลและไฟล์ `mmproj` (คู่ที่แนะนำ) แล้วเปิด "ให้ AI ดูภาพหน้าจอ" ในแท็บตั้งค่า |

## 8. สิ่งที่ยังไม่มี (โดยตั้งใจ)

- ไม่มี auto-download / auto-update เบื้องหลัง — ทุกอย่างเริ่มจากปุ่มของคุณ
- ไม่รับประกันความเร็ว GPU ต่อการ์ดรุ่นใดรุ่นหนึ่ง; โมเดลใหญ่แย่ง RAM/VRAM กับเกม
- ไม่ได้ทดสอบบน Windows ในรีโปนี้ (เทสต์รันบน Linux sandbox ด้วย transport จำลอง) — โปรดทดสอบกับเครื่องจริงก่อนใช้แข่ง/สตรีม
- ไม่ใช้ `wget`/`curl` ภายนอก ไม่ติดตั้ง service, ไม่แตะ PATH ของระบบ และไม่แก้ไฟล์นอกรวมทั้งไม่แตะไฟล์ของคุณนอกโฟลเดอร์ข้อมูลของผู้ใช้
- ไม่ได้ทำ UI สำหรับลบโมเดลในแอป (ลบไฟล์ใน `llama/models` เองได้ หรือกดล้างข้อมูล)
- ไม่มี GPU/รุ่นที่ "แนะนำที่สุด" — แคตตาล็อกเป็นเพียงจุดตั้งต้น
