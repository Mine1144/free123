# AI ตัวละคร: อ่านสีหน้า จำหน้า คิดวิธีพูด และวิจัยเกมก่อนแปล

เอกสารนี้อธิบายการทำงาน *จริง* ของสี่ฟีเจอร์ที่เพิ่มเข้ามา พร้อมข้อจำกัดที่ต้องรู้ เพื่อไม่ให้ผู้ใช้เข้าใจว่าแอปเก่งเกินจริง ทุกอย่างที่เกี่ยวกับใบหน้าคำนวณในเครื่องและไม่ส่งภาพออกจากเครื่อง

## เส้นทางข้อมูลหนึ่งรอบ

```
จอ → จับภาพ (ในเครื่อง) → OCR (ในเครื่อง)
      → layout: บทบาทของแต่ละกล่อง + ผู้พูดจาก "ป้ายชื่อ" ที่เห็นจริง
      → vision (ในเครื่อง): กล่องใบหน้า + การวัดสีหน้า + descriptor
      → FaceMemory: track id คงที่ → เทียบคลังหน้า → ชื่อที่ผู้ใช้ยืนยันเท่านั้น
      → speech plan: การ์ดตัวละคร + หลักฐานจากบทพูด → แผนสรรพนาม
      → research brief (ถ้ามี, ยังไม่ยืนยัน) + โปรไฟล์เกม
      ↓ รวมเป็น prompt เดียว
   AI แปลเป็นไทย (JSON) → ตรวจ/จัดคิว → Overlay + DialogueMemory (RAM)
      → Store.learn: สรุปเรื่อง/ความสัมพันธ์/ตัวละคร → โปรไฟล์เกม
```

สองระดับของบริบทถูกแยกกันเสมอ: **โปรไฟล์เกม** (notes, glossary, การ์ดตัวละคร, brief) กับ **เฟรมปัจจุบัน** (กล่องข้อความ, ป้ายชื่อ, ใบหน้า, แผนพูด, บทพูดล่าสุด) ทุกชิ้นมีป้ายที่มาว่า `ผู้ใช้ยืนยัน` / `วัดได้` / `ยังไม่ยืนยัน` และ AI ถูกสั่งให้เชื่อผู้ใช้ก่อนเสมอ

## 1. อ่านสีหน้าตัวละคร

**ทำงานในเครื่องทั้งหมด** ด้วย backend ตามลำดับ:

| backend | ต้องการ | ให้อะไร |
|---|---|---|
| `mediapipe` | ติดตั้ง extra `.[faces]` | FaceMesh 478 จุด → วัดได้ละเอียด (ตา/ปาก/คิ้ว/เอียงศีรษะ/สายตา) |
| `opencv` | ไลบรารี OpenCV (มีอยู่แล้ว) | ตรวจจับใบหน้าแบบ Haar และถ้ามีไฟล์ ONNX ที่ผู้ใช้ตั้ง (`face_model`) จะใช้ YuNet |
| ปิด | — | ไม่วิเคราะห์ใบหน้า พร้อมบอกเหตุผลบนแท็บตัวละคร |

ค่าที่วัดจากภาพนิ่ง (ไม่ใช่การตรวจจับอารมณ์):

- `mouth_open` ช่องปากเทียบความกว้างปาก · `smile` มุมปากยกขึ้น (+) หรือต่ำลง (−)
- `eye_open` อัตราส่วนเปิดตา (กะพริบ/หลับ) · `brow_raise` ระยะคิ้ว–ตา · `tilt_deg` ความเอียงศีรษะ · `gaze_x` ตำแหน่งรูม่านตา

**หนึ่งภาพ = หนึ่งการวัด ไม่ใช่คำตัดสินอารมณ์** ป้ายข้อความมีแค่ข้อเท็จจริงสุดขั้ว เช่น `หลับตาหรือกะพริบ`, `อ้าปากกว้าง` ส่วนค่าอื่นเป็นตัวเลขที่ AI ใช้ประกอบ *พร้อมภาพ* และถูกสั่งให้พูดแบบ "ดูเหมือน…" ไม่ใช่ "โกรธ 100%"

**Baseline ต่อตัวละคร**: ระบบเก็บค่าล่าสุดแบบเลื่อน (สูงสุด 10 ครั้ง) ต่อ track id แล้วรายงาน *การเปลี่ยน* เทียบค่ามัธยฐานของตัวเอง — เช่น "ปากเปิดมากกว่าปกติของตัวเอง (+0.35)" หรือ "ปากขยับไปมาหลายจังหวะ (น่าจะกำลังพูด)" ซึ่งใช้แยก "ตัวละครนี้กำลังพูด" จาก "ใบหน้านิ่งประกอบฉาก" ได้โดยไม่ต้องได้ยินเสียง

ข้อจำกัดที่ควรรู้: เป็นการวัดเรขาคณิตบนภาพนิ่ง ไม่ใช่ FACS หรือโมเดลอารมณ์ที่ผ่านการรับรอง; ทรงผม แสง มุมกล้อง และสไตล์การ์ตูน/โมเดล 3D ทำให้ค่าเพี้ยนได้; ไม่มี audio, ไม่มีการอ่านปากจากวิดีโอ, ไม่มีการรับประกันอารมณ์ที่ถูกต้อง

## 2. จำหน้าตัวละคร

- **Tracker**: จับคู่กล่องใบหน้าระหว่างเฟรมด้วย IoU (≥0.25) และ ttl 6 เฟรม → `track id` คงที่พอจะดู trend และอ้างถึง "ใบหน้าที่ 3" ได้
- **Descriptor**: เวกเตอร์ตัวเลขที่คำนวณในเครื่อง (โครงสร้างไล่ระดับสี + สีของใบหน้า) **ไม่ใช่ neural arcface** และไม่มีการส่งภาพใบหน้าไปที่ไหน
- **การตัดสินชื่อ**: ใช้ชื่อ *ที่ผู้ใช้ยืนยันแล้ว* เมื่อคะแนน ≥ `0.86` **และ**ชนะอันดับสอง ≥ `0.02`; ถ้าได้ ≥ `0.78` จะเป็นเพียง "อาจเป็น X" ซึ่งถูกสั่งห้ามใส่ในบทแปล; ต่ำกว่านั้นคือ "ไม่ทราบ" (ระบบไม่แต่งชื่อหรือเพศให้)
- **คลังต่อโปรไฟล์เกม**: สูงสุด 60 ตัวละคร, 8 descriptors/คน เก็บใน JSON (`characters`) พร้อมสีผม/ตา/ชุดที่วัดได้ — **ไม่เก็บภาพครอปหรือภาพหน้าจอลงดิสก์**
- **การยืนยันของมนุษย์**: ปุ่ม *สแกนใบหน้าจากพื้นที่ที่เลือก* → *ผูกชื่อนี้กับใบหน้าที่เลือก (ยืนยันโดยผู้ใช้)*; ข้อเสนอที่ AI ส่งมาจะเข้าคิว *ข้อเสนอผูกชื่อ* และต้องกด *ยืนยันข้อเสนอที่เลือก* หรือ *ปฏิเสธ* ก่อนจึงจะกลายเป็นชื่อจริง
- **ลืม**: *ล้างใบหน้า* (ลบ descriptors แต่ยังเก็บการ์ด) และ *ลบ* (ลบทั้งการ์ด)

ข้อจำกัด: คนหน้าคล้ายกัน เครื่องแบบ/ชุดเปลี่ยน ตัวละครหันหลัง หรือแสงน้อย อาจ match ผิดหรือไม่ match; เป็นตัวช่วยจำ *ในเซสชันและโปรไฟล์เดียวกัน* ไม่ใช่ระบบยืนยันตัวตน และไม่ควรใช้กับข้อมูลอ่อนไหว

## 3. คิดว่าตัวละครต้องพูดอย่างไร

**การ์ดการพูด** ต่อตัวละคร (แก้เองได้ทั้งหมด): สรรพนามแทนตัวเอง, สรรพนามเรียกอีกฝ่าย, คำลงท้าย, ระดับภาษา, เอกลักษณ์การพูด, เพศ *ที่ผู้ใช้ยืนยันเท่านั้น*, อาวุโสเทียบคู่สนทนา และความสัมพันธ์ — ติ๊ก *ล็อกการ์ดนี้* แล้ว AI ต้องใช้ค่านั้นและห้ามเปลี่ยน

**หลักฐานอัตโนมัติจากบทพูดจริง** (`speech.analyse_source`): ภาษา, คำสุภาพ, คำเรียกเครือญาติ/คำเรียกขาน (เช่น 先輩 → รุ่นพี่), คำสรรพนามที่ปรากฏ, ระดับความสุภาพ, อาวุโสสัมพัทธ์ และร่องรอยเพศ *จากถ้อยคำ* (ไม่ใช่จากหน้าตา)

**แผนถูกประกอบจาก**: ค่าที่ล็อกโดยผู้ใช้ → preset ตามความสัมพันธ์ (พี่น้อง/พ่อแม่ลูก/ปู่ย่าตายาย/คู่รัก/เพื่อน/เพื่อนสนิท/รุ่นพี่รุ่นน้อง/ครูกับนักเรียน/เจ้านายกับลูกน้อง/ศัตรู) → อาวุโส → เพศที่ยืนยัน → โทนจากตัวบท จากนั้นแผนถูกส่งไปใน `speech_plans` ของ prompt พร้อม `must_follow`, `locked` และ `source_evidence`

**ตรวจหลังแปล** (`speech.check_translation`): เตือนเมื่อคำลงท้าย/สรรพนามไม่ตรงเพศที่ยืนยันหรือไม่ตรงแผนที่ล็อก เพื่อให้ผู้ใช้แก้ `self_pronoun`, `address`, `particles` ของบรรทัดนั้นได้

ข้อจำกัด: ภาษาไทยเลือกคำตามความสัมพันธ์และอารมณ์มากกว่ากฎตายตัว; preset เป็น *ข้อเสนอจากหลักฐาน* ไม่ใช่ความจริง; โมเดลอาจไม่ทำตามแผน → ต้องดูคำเตือน QC และแก้ในการ์ด

## 4. วิจัยเกมก่อนแปล (opt-in)

ช่องทางข้อมูลสามทาง เลือกใช้ร่วมกันได้:

1. **ลิงก์ที่คุณให้** (HTTPS, host สาธารณะเท่านั้น) สูงสุด 6 หน้า
2. **ข้อความที่คุณคัดลอกมาเอง** (นิยาย/บทสรุป/วิกิ)
3. **ผู้ให้บริการค้นเว็บ**: SearXNG (ในเครื่องได้), Brave, Serper, Tavily หรือ custom endpoint — ใช้ key ของคุณ เก็บใน Windows Credential Manager

ขั้นตอน: ตรวจชื่อเกม/ชื่ออื่น → ดึงหน้าเว็บ (ตัดข้อความ, ไม่ตาม redirect ข้ามโดเมน, จำกัดชนิด `text/html`) → ให้ AI สรุปเป็น JSON brief → `merge_brief` โดย **การแก้ของผู้ใช้ชนะเสมอ** → เก็บในโปรไฟล์เกม (ใช้ซ้ำได้ ไม่ต้องค้นใหม่ทุกครั้ง)

**การยินยอม**: ก่อนค้นเว็บจริง แอปถามว่า "จะส่งคำค้น (ชื่อเกม) ไปที่ … ไม่มีการส่งภาพหน้าจอหรือข้อความในเกมในการค้นหา" ติ๊ก *ค้นคว้าอัตโนมัติตอนเริ่มแปล* ได้ แต่จะทำ **หนึ่งครั้งต่อเกม** และส่งเฉพาะชื่อเกม

**เข้า prompt แบบไหน**: `game_research_unverified` ขึ้นต้นด้วยคำเตือน "ข้อมูลนี้มาจากการค้นคว้า ยังไม่ยืนยัน: ถ้าขัดกับข้อความบนจอ ให้เชื่อข้อความบนจอ" ตามด้วยช่อง *ผู้ใช้ยืนยันเอง (สำคัญที่สุด)* แล้วจึงข้อมูลอื่น (ตัวละคร, คำศัพท์, เรื่องย่อ) แบบมีเพดานความยาว

ข้อจำกัด: ข้อมูลวิกิ/แฟนคลับอาจผิดหรือสปอยล์; ชื่อเกมซ้ำกันได้; การสรุปของโมเดลอาจเข้าใจผิด จึงต้องตรวจในช่อง *สิ่งที่คุณยืนยันเอง*; ผู้ให้บริการค้นเว็บอาจมีค่าใช้จ่ายตามบัญชี

## 4.1 ชุดคุณภาพการแปล (ทำงานร่วมกับสี่ข้อข้างบน)

| กลไก | ทำอะไร | หลักฐานที่ใช้ตัดสิน | ปิดได้ที่ |
|---|---|---|---|
| หน่วยความจำคำแปล | ใช้คำที่คุณยืนยันแล้วซ้ำเมื่อข้อความเดิมปรากฏอีกครั้ง | ข้อความต้นฉบับ (normalise แล้ว) + ลายเซ็นการ์ดเสียง + ไม่มีคำเตือน QC | `translation_memory` |
| ผสานบรรทัดซับ | รวมบรรทัดต่อเนื่องเป็นประโยคเดียวก่อนแปล | ตำแหน่ง/ความสูง/บทบาทตรงกัน, ผู้พูดเดียวกันหรือบรรทัดต่อมาไม่มีป้ายชื่อ, ยังไม่จบประโยค, ≤3 บรรทัด, ≤400 ตัวอักษร | `merge_lines` |
| ขุดคำศัพท์ | เสนอ glossary จากชื่อ/คำที่ซ้ำ | ปรากฏ ≥2 บรรทัดที่ต่างกัน + คำไทยร่วมกันในคำแปล + ต้องไม่โผล่ในบรรทัดที่ไม่มีคำนั้น | `glossary_mine` |
| รอบตรวจความสม่ำเสมอ | ให้ AI แก้เฉพาะบรรทัดที่ผิด glossary หรือขัดการ์ดที่ล็อก | เช็กในเครื่อง (`check_terms`, `check_translation`) ก่อน แล้วจึงเรียก AI หนึ่งครั้ง | `review_consistency` |
| ตรวจสุขภาพระบบ | บอกว่าอะไรใช้ได้จริงบนเครื่องนี้ | ลองใช้จริงทีละส่วน (ยกเว้นการเชื่อมต่อที่ต้องกดยินยอมก่อน) | ปุ่มในแท็บตั้งค่า |

ผลข้างเคียงที่ตั้งใจ: เมื่อใช้หน่วยความจำคำแปล ข้อความที่ซ้ำจะไม่ถูกส่งให้ AI และจะไม่ปรากฏในตารางประวัติ (ตารางเก็บบรรทัดที่ AI เพิ่งแปล) แต่ยังแสดงบน overlay และนับไว้ในสถานะ "ใช้คำแปลที่คุณเคยยืนยันไว้ N บรรทัด"

## 5. ความเป็นส่วนตัวและการปิด/ลบ

- ภาพหน้าจอ, การตรวจจับ/วัดใบหน้า, descriptor, tracker และบทพูดล่าสุด (`DialogueMemory`) อยู่ในเครื่องและ RAM ทั้งหมด — ส่งออกเฉพาะ *ข้อความสรุป* ที่ประกอบใน prompt เท่านั้น
- เก็บลงดิสก์เฉพาะ: การ์ดตัวละคร + descriptors + สี (JSON โปรไฟล์, **ไม่เข้ารหัส**), brief วิจัย, notes/glossary/สรุปเรื่อง, หน่วยความจำคำแปล (คู่ข้อความต้นฉบับ↔คำแปลไทยของคุณ) และข้อเสนอ glossary — ไม่มีภาพ
- ปิดฟีเจอร์: `การวิเคราะห์ใบหน้า` = ปิด, หรือเลือก backend `ปิด`; `expression_cues` ปิดการส่งค่าสีหน้า; `research_search` = off และปิด *ค้นคว้าอัตโนมัติ*
- ลบข้อมูล: *ล้างใบหน้า* / *ลบ* การ์ด, *ล้างข้อมูลวิจัย*, หรือลบโฟลเดอร์ `%LOCALAPPDATA%\ScreenThai`

```powershell
.venv\Scripts\python -m pip install -e ".[dev,faces]"   # faces = mediapipe สำหรับการวัด 478 จุด
.venv\Scripts\python -m pytest -q
```

- ไม่ติดตั้ง `.[faces]` ก็ใช้ได้: ระบบจะลดระดับเป็น OpenCV หรือปิดใบหน้าพร้อมบอกเหตุผล การแปลยังทำงานปกติ
- ทดสอบกับภาพจริง: ตั้ง `SCREEN_THAI_FACE_FIXTURE=<path รูปใบหน้า>` แล้วรัน `pytest tests/test_vision.py` (ใน sandbox ที่ไม่มีฟอนต์ไทย การทดสอบ UI จะตรวจเชิงตรรกะ/เมตริก ไม่ได้ตรวจว่ารูป glyph ถูกต้อง)
